# opc-bootstrap-validator · OPC 启动验证器

把《方法论全文（OPC 单人创业自查与最小验证流程）》的表格判据固化为确定性计算，产出中性的 HTML 决策书。

- 当前版本：**v0.6.0**（两层闸门全部实现）
- 引擎：`scripts/gate.py`（Python 标准库零依赖）
- 命名：skill 标识 `opc-bootstrap-validator`，中文显示名「OPC 启动验证器」
- 报告名《OPC 最小验证决策书》。

## 自足性与职责边界

本 skill 完全自足，不依赖任何其他 skill。输入全部由自己提问收集，不读取、不修改外部产物，也不假设环境里存在任何"定方向"类的工具。

职责上它只回答一个问题：这个方向能不能开始、还差哪些证据。它不负责替你选方向：方向的产生被设计成闸门 3 内部的第一个动作（第四章四类证据 → 3–5 个候选），不从外部输入。

## 两层闸门

**第一层 · 五道通用闸门**（所有 OPC 通用）

| 闸门 | 章节 | 命令 | 核心判据 |
|---|---|---|---|
| 1 生存与合规 | 第二章 | `gate1` | 6 条硬红线（一票否决）+ 7 条软风险 + 止损三数字 + 安全垫月数 |
| 2 能力与资源 | 第三章 | `score` | 16 项加权满分 100；无证据一律封顶 2 分 |
| 3 问题与客户 | 第四、五章 | `direct` + `funnel` | 四类证据出方向 → 9 项评分卡（三项硬约束 <3 分即不合格）→ 预验证门槛 → 八环节漏斗 |
| 4 付费与交付 | 第六、七章 | `mso` + `delivery` | 19 字段一页纸 + 7 条最低标准（必须收费、禁绝对化表述）+ 首 3 客户 7 条 |
| 5 单位经济 | 第六章 6.3 | `econ` | 单客贡献利润 / 贡献利润率 / 有效时薪 / 获客回本周期 |

外加两条横切能力：`signal`/`scan`（伪验证信号拦截 + 4 级信号分级）、`stop`（止损与退出监控 + 6 条替代路径）。

五道闸门是 AND 关系：任何一道缺证据，结论都被压到 `CONDITIONAL` 以下。评分只能往下压，不能往上抬；被压制的档位会在报告里单列一张表说明。

**第二层 · 模式专属指标**（模式库 8 类 / 69 模式 / 29 指标包）

| 命令 | 章节 | 核心判据 |
|---|---|---|
| `modes` | 第十二章 12.2 / 12.3 | 先按「主要收入来源 + 主要风险来源」定第一模式，再取该模式的专属指标包；混合模式带出叠加包 |
| `board` | 第十二章 12.4 + 第九章 9.1 / 9.2 | 北极星 1 + 过程 2 + 安全 2 五槽位 + 通用 6 类周看板 + 继续/调整/暂停决策 + 记录格式 11 项 |

两层是 AND 关系：第二层数据再漂亮，第一层任一道不过也只能输出「仅副业」；第一层过了但第二层没出现该模式应有的增长信号，同样不构成扩大投入依据。

两道**硬拒绝**（防反用模式目录选赛道）：
- 没有合格候选方向就跑 `modes` → `BLOCKED_ORDER`，退出码 4；
- 只给方向名、没给主要收入来源 → `NEEDS_INPUT`，回问「你的钱主要从哪来」，**不硬套一个模式**。
