# 第二层：模式地图与合并看板

> **随引擎 v0.8.1 更新** · 2026-09-16

出处：《方法论全文》第十二章 12.2 / 12.3 / 12.4 + **第九章 9.1 / 9.2**。
模式库数据在 `assets/modes.json`（8 类 / 69 模式 / 29 指标包），本文件是它的可读索引与用法说明。

两层是 AND 关系。第二层回答「这种具体模式是否出现了该模式应有的真实增长信号」，它不能替代第一层：任何模式都必须先满足合规和止损要求（12.1 末段 / 12 章末）。

## 一、定模式的两条硬规则

1. 顺序上先有方向，才有模式。必须先由第四章四类证据生成 3–5 个候选方向并完成评分，再用模式地图归类。模式目录不得反用于选题，它的用途是选指标。
2. 第一模式由「主要收入来源 + 主要风险来源」决定。一个业务可能同时属于多个类别，此时按主要收入来源定第一模式，其余只作为**叠加模式**取指标。

引擎据此设了两道拒绝：没有合格候选方向 → `BLOCKED_ORDER`（退出码 4）；只给了方向名称、没给收入来源 → `NEEDS_INPUT`，回问「你的钱主要从哪来？」，不硬套一个模式。

> 常见误用：拿「模板」「咨询」「AI」这类词命中去反推模式。「帮跨境小卖家整理客服知识库与回复模板」里的「模板」是交付物的一部分，不意味着这是卖模板的生意，它可能是产品化服务。所以引擎用词长 × IDF 压制通用词，并且只在收入来源存在时才给高置信度归类。

## 三、29 个专属指标包（12.3）

每个包四组指标：**核心验证信号**（有没有人真的在用/买）、**必看经营指标**（效率与质量）、**单位经济或持续性指标**（赚不赚钱）、**主要专属风险**（会不会因平台/合规/交付失控）。

| key | 模式大类 | 核心验证信号 | 主要专属风险 |
|---|---|---|---|
| `P01` | 专业服务、顾问、自由职业 | 多个客户签约并回款 | 范围蔓延、坏账、责任边界、过度依赖个人时间 |
| `P02` | 产品化服务、代运营、托管 | 客户购买标准化套餐并续费 | 服务承诺失控、客户数据、平台授权、结果不可控 |

## 四、看板：1 + 2 + 2 五槽位（12.4）

不要试图一次追踪全表。每个模式只挑：

| 槽位 | 数量 | 要求 |
|---|---:|---|
| 北极星指标 | 1 | 最能代表客户持续获得价值的指标，例如付费用户留存、签收订单、有效订阅、完成交付或读者追读。 |
| 过程指标 | 2 | 能解释北极星指标变化的动作，例如有效访谈、激活率、提案接受率、内容发布稳定性或发货及时率。 |
| 安全指标 | 2 | 防止表面增长掩盖损失的指标，例如贡献利润、退款率、现金流、投诉率、数据事件或有效时薪。 |

引擎会把该模式指标包拆成候选池（过程 = 经营指标拆分；安全 = 单位经济 + 风险拆分），让用户从候选里挑，而不是自己想指标。

### 记录格式（11 项，12.4）

```text
我的 OPC 模式：
主要收入来源：
第一层五道闸门当前状态：
北极星指标：
过程指标 1：
过程指标 2：
安全指标 1：
安全指标 2：
本周期目标：
继续、调整或暂停条件：
数据来源和复盘日期：
```

其中「我的 OPC 模式」「主要收入来源」「第一层五道闸门当前状态」以及五槽位对应的 5 个字段，由引擎自动回填，不需要重复录入。

## 六、继续 / 调整 / 暂停决策表（9.2）

引擎按顺序命中第一条，并输出命中的依据，便于复核。

| 命中条件 | 决策 |
|---|---|
| 连续两个周期有付款，交付可控，单位经济改善 | 继续，逐步标准化和提高价格 |
| 有访谈和提案，但无付款 | 优先调整客户、痛点、信任证明或 Offer，不急于扩张 |
| 有付款但长期亏损或严重超时 | 缩小范围、提高价格、改变交付方式或停止该 Offer |
| 只有单一客户贡献大部分收入 | 先降低集中度，再考虑全职投入 |
| 健康、家庭、现金流明显恶化 | 立即降级为副业、暂停或退出 |
| 两轮有记录验证仍无付款证据 | 返回适配复评或切换替代路径 |

实际判定优先级如下（无付款属于生存问题，排在集中度这类扩张前置条件之前）：

1. 命中立即停止条件（10.1）→ 立即降级为副业/暂停
2. 硬红线命中（2.1）→ 只允许低成本副业测试
3. 现金或时间超限 → 暂停
4. 建议停止/转向命中，或两轮无付款（10.2 / 7.3）→ 复评或切换替代路径
5. 无付款证据 → 先改客户 / 痛点 / 信任证明 / Offer，不急着扩张
6. 有付款但单位经济为负或数据不全 → 缩范围 / 提价 / 改交付方式
7. 单一客户收入占比 > 50% → 先降集中度，再谈全职
8. 连续 ≥2 周期有付款、交付可控、单位经济达标（且止损监控为 KEEP）→ 继续，逐步标准化与提价

## 七、怎么驱动引擎

```bash
# 1) 归类（需要 gate3.directions 里已有合格方向）
python3 scripts/gate.py modes --config opc_input.json

# 2) 合并看板：不加 --out 打印 JSON，加了则出 HTML
python3 scripts/gate.py board --config opc_input.json
python3 scripts/gate.py board --config opc_input.json --out 第二层看板.html

# 3) 决策书附加第二层两节（配置里有 layer2 时自动追加 §11 / §12）
python3 scripts/gate.py report --config opc_input.json --out OPC决策书.html
```

输入字段（`layer2`）：

| 字段 | 用途 |
|---|---|
| `mode_key` | 显式指定模式 key（如 `A05`），跳过关键词匹配 |
| `direction` | 选中的候选方向名（必须来自闸门 3 的产出） |
| `revenue_source` | **主要收入来源**——定第一模式的主依据 |
| `risk_source` | 主要风险来源——定第一模式的次依据 |
| `description` | 业务补充描述 |
| `overlays` | 叠加模式的指标包 key 列表（不给则用该模式的默认叠加） |
| `slots` | `north_star` / `process[]` / `safety[]` 五槽位 |
| `metrics` | 通用 6 类看板的本周期填写值 |
| `concentration` | 最大单一客户收入占比（0–1），> 0.5 触发降集中度 |
| `cycles_paid` | 已连续有付款的周期数，≥ 2 才可能判「继续」 |
| `record` | 记录格式 11 项的手填值 |

## 八、边界与反模式

| 情况 | 处理 |
|---|---|
| 没有合格候选方向就跑 `modes` | 拒绝（`BLOCKED_ORDER`，rc=4），不返回任何模式建议 |
| 只给方向名、没给收入来源 | `NEEDS_INPUT`，回问收入来源；候选只作参考 |
| 前两名得分接近 | 标 `ambiguous`，要求与用户确认后再锁指标 |
| 只是描述了业务形态、没有量化指标 | 槽位留空，报「待填」并给候选池，不替用户填 |
| 第一层没通过 | 看板照出，但顶部明示「不构成扩大投入依据」，并回显第一层结论与缺口 |
| 混合模式（H 类） | 第一模式取混合包 P29，同时给出各组成部分的叠加包指标 |
| 用户想让看板「好看一点」 | 拒绝。指标数值必须用户原样填写，缺失一律标「待填」 |
