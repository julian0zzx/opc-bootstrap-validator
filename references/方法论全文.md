# OPC 单人创业自查与最小验证流程

> 本文件是 `opc-bootstrap-validator` 判据引擎的**方法论出处**。
> 引擎中的每一个阈值、权重、封顶规则与判定档位，都可在本文对应章节找到依据。
> 章节对应关系见 `SKILL.md` 的「判据与章节对照」表。

> 核心原则：先验证商业闭环，再扩大投入。验证完成之前，暂不辞职、不注册公司、不做完整官网、不购买重资产设备。需要优先确认的是：是否存在明确客户、客户是否愿意真实付款、交付能否由一个人完成、每单是否留下合理利润，以及业务能否合法且可持续。

> **适用范围：** 本流程适用于以个人为核心、借助 AI 和数字工具提供专业服务、知识产品、数字产品、轻量自动化或细分电商服务的早期 OPC（One-Person Company，单人公司/单人创业）尝试。涉及特许经营、医疗、法律、金融、教育培训、跨境数据、食品、广告等受监管行业时，必须额外完成当地法律与资质核查。

---

## 一、先看结论：五道闸门

OPC 检验的是能否持续为特定人群创造可付费价值，与「想不想自由」无关。建议按照以下闸门逐级推进。

| 闸门 | 要回答的问题 | 通过条件 | 未通过处理 |
| --- | --- | --- | --- |
| 1. 生存与合规闸门 | 现在是否能安全试跑？业务是否合法？ | 基本生活、家庭责任、健康状态可承受；完成资质、合同、税务和数据风险初查 | 只做低成本副业测试，或更换业务 |
| 2. 能力与资源闸门 | 是否具备完成一次闭环的条件？ | 能独立获客、报价、交付、收款，或有明确的补短板方案 | 先修复短板，不全职启动 |
| 3. 问题与客户闸门 | 是否有具体人群正在为问题付出代价？ | 访谈和现有行为证明问题真实、频繁、优先级足够高 | 调整客户人群或痛点 |
| 4. 付费与交付闸门 | 客户是否愿意为最小方案付款？ | 至少 1 个真实付费客户，交付完成且客户认可 | 调整 Offer、价格或交付范围，限轮次重试 |
| 5. 经济与可持续闸门 | 这是否值得继续投入？ | 单位经济为正，交付工时可控，现金流和获客路径有改善趋势 | 缩小范围、转向、暂停或退出 |

**重要区分：** 口头兴趣只是信号，愿意留下联系方式是弱信号，愿意预约并提供业务信息是中等信号，只有支付定金或全款才算强验证。没有付款，不应把方向称为已验证。

## 二、闸门 1：前置硬红线筛查

### 2.1 硬红线

以下任意一项成立，暂不进行全职 OPC，只允许在不影响主业、家庭和健康的前提下做低成本测试。

1. 没有经过核算的生活费安全垫，且短期内没有稳定现金流来源。
2. 业务需要强制资质、许可、备案或特定执业资格，而当前无法合法取得或借用合规主体承接。
3. 业务可能触及人身安全、重大财产损失、个人敏感信息、未成年人信息、版权或商业秘密，但尚未建立相应的风险控制方案。
4. 个人健康、心理状态、照护责任或家庭关系已经处于明显失衡状态。
5. 全职尝试会导致高息负债、基本生活中断、重要家庭义务无法履行，或无法承担最坏情形。
6. 计划依赖违法获客、虚假宣传、侵权素材、未经授权的数据或规避平台规则。

「6–12 个月生活费」只作参考，不宜机械套用。更稳妥的算法是：安全垫月数 = 可动用现金 ÷ 每月最低必要支出。有抚养、房贷、医疗或收入波动较大责任的人，应采用更保守的安全垫和止损期限。

### 2.2 软风险项

以下项目不必然否决，但每命中一项都应写入修复计划：

- 从未独立完成「获客—报价—签约—交付—收款—售后」的完整闭环。
- 极度排斥销售、沟通、谈判或被拒绝。
- 主要动机只是逃离职场，尚未确认愿意长期承担客户结果。
- 只愿意执行任务，不愿意进行客户选择、定价、取舍和业务判断。
- 对目标客户缺乏真实接触，主要依靠想象判断需求。
- 业务方向依赖单一平台、单一客户或单一工具。
- 对合同、发票、税务、知识产权、数据安全和售后边界没有基本认识。

### 2.3 三个必须写下来的止损数字

在任何付费测试开始前，先写明：

| 止损项 | 写法 | 示例 |
| --- | --- | --- |
| 最大现金投入 | 在不影响生活的前提下最多投入多少 | 不超过可支配现金的 5% |
| 最长试跑时间 | 在达到复盘点前最多投入多久 | 8 周或 3 个验证周期 |
| 最低结果 | 达到什么结果才继续 | 至少 2 个付费客户，单客毛利为正 |

写下止损数字，是为了防止在没有证据时不断追加投入。

## 三、闸门 2：OPC 适配度评分，但必须用证据打分

### 3.1 评分规则

每项按 0–5 分评分，并为每项附上证据。只有「我觉得我可以」而没有事实记录时，最高只能打 2 分。

- **0 分：** 没有能力、资源或行为证据。
- **1–2 分：** 有兴趣或零散经验，但不能稳定复现。
- **3 分：** 曾经完成过，或正在按计划练习。
- **4 分：** 能独立稳定完成，并有案例、回款或可验证记录。
- **5 分：** 已形成可复用方法，能够持续产生结果或教会他人。

| 维度 | 评估项 | 权重 | 得分 | 证据或待补证据 |
| --- | --- | ---: | ---: | --- |

|  | 接受不确定性，并能在没有外部监督时推进 | 5 |  |  |
|  | 能长期承担销售、交付、售后和复盘 | 5 |  |  |
|  | 在连续被拒绝时仍能调整而非停摆 | 5 |  |  |
| 能力闭环 | 曾独立完成项目并成功收款 | 10 |  |  |
|  | 具备可对外售卖的专业能力或可验证成果 | 8 |  |  |
|  | 能判断业务边界、风险和不适合服务的客户 | 6 |  |  |
|  | 能学习并执行获客、报价和谈判 | 6 |  |  |
| 资源与风险 | 有可核算的现金安全垫或稳定现金流 | 8 |  |  |
|  | 每周可稳定投入时间，家庭责任已安排 | 6 |  |  |
|  | 了解基本合同、财税、知识产权和数据安全要求 | 6 |  |  |

|  | 已有低成本、可重复触达客户的渠道 | 5 |  |  |
| OPC 结构 | 交付可以标准化，AI 能提高效率而非替代责任 | 5 |  |  |

| **合计** |  | **100** |  |  |

### 3.3 结果解释

- **80–100 分：** 具备较好起点，但仍必须先做副业或低风险付费验证，不因分数高而直接裸辞。
- **60–79 分：** 有条件适配。制定 3–6 个月短板修复计划，修复期内不全职启动。
- **0–59 分：** 当前不适配。优先获得真实案例、补充现金储备、训练销售或选择替代路径。

**叠加规则：** 软风险项命中 3 项及以上时，即使总分达到 80 分，也只能副业验证。评分不能覆盖硬红线，也不能替代真实付款证据。

### 3.4 短板修复计划

修复计划需要写清动作、频率、证据和截止时间，只写「提升能力」不算计划。

| 短板 | 修复动作 | 期限 | 达标证据 |
| --- | --- | --- | --- |
| 缺少闭环经验 | 承接 1 个范围明确的小单，完整完成签约、交付、收款和售后 | 1–2 个月 | 合同、回款记录、交付物和客户反馈 |
| 不清楚能卖什么 | 选择一个细分人群，完成作品集和 3 个案例拆解 | 1–3 个月 | 一页 Offer、作品集、案例说明 |
| 销售恐惧 | 完成 20 次有效触达和 10 次结构化访谈 | 30 天 | 联系记录、访谈纪要、异议清单 |
| 现金储备不足 | 降低固定支出，维持主业或增加稳定收入 | 3–12 个月 | 安全垫月数达到个人目标 |
| 交付不可重复 | 记录每一步交付工时、输入、输出、验收标准 | 4–8 周 | SOP、模板、质量检查表 |
| 合规知识不足 | 完成所在地的主体、合同、税务、资质、数据和版权初查 | 2–4 周 | 风险清单和处理方案 |

短板修复的最低目标建议为：至少 1 个真实付费客户、一次完整回款、一个可重复交付流程、一个可持续触达渠道，以及一份风险清单。

## 四、闸门 3：选择方向，而不是选择「热门赛道」

### 4.1 方向生成

从以下四类证据出发，生成 3–5 个候选方向：

1. 过去 3–5 年中反复做过、做出结果且不完全依赖单一雇主的事情。
2. 他人反复向你咨询、请你代办或愿意为你节省时间的事情。
3. 你接触过的行业中，客户已经在花钱解决但现有方案不理想的问题。
4. 你能够在 14 天内完成最小交付，并能明确验收标准的服务。

候选方向不要写成宽泛的能力标签，要写成「客户人群 + 使用场景 + 结果 + 交付形式」。以「AI 咨询」为例，合格的写法是「帮助跨境小卖家在 7 天内整理客服知识库和回复模板，减少重复客服工时」。

### 4.2 方向评分卡

每项 1–5 分，并写出事实依据。以下权重比单纯相加更能突出商业可行性。

| 评分项 | 权重 | 关键问题 |
| --- | ---: | --- |
| 痛点和损失强度 | 20% | 不解决会造成收入损失、成本增加、合规风险或大量时间浪费吗？ |
| 已有付费证据 | 20% | 客户是否已经为相似方案付费，或愿意支付定金？ |
| 客户可触达性 | 15% | 你能否低成本找到并持续触达这类客户？ |
| 结果可衡量性 | 10% | 交付后能否用时间、成本、收入、转化率或风险指标验收？ |
| 交付可控性 | 10% | 单人能否在约定时间内完成，且不依赖不可控第三方？ |
| 单位经济 | 10% | 扣除直接成本和交付工时后，是否仍有合理毛利？ |
| 复购与转介绍 | 5% | 需求是否会重复出现，或客户是否容易介绍同类客户？ |
| 合规与依赖风险 | 5% | 是否存在资质、数据、平台、版权或单一客户风险？ |
| 个人耐久度 | 5% | 你是否愿意持续做至少 2–3 年？ |

建议优先选择总分较高、且「合规、客户触达、交付不可控」三项均不低于 3 分的方向。个人耐久度只是约束条件，补不了一个没有市场的方向。

### 4.3 三个筛选原则

- **竞争筛选：** 不必回避竞争，但要避开大厂可以用标准化低价产品直接替代的场景。优先寻找细分行业、复杂流程、强信任和需要判断的场景。
- **AI 筛选：** AI 应降低检索、整理、生成和重复执行成本，但最终的事实核验、行业判断、客户沟通和结果责任仍由人承担。
- **轻交付筛选：** 启动成本低、范围清楚、交付周期短、验收标准明确，并且可逐步模板化。

## 五、闸门 3 的验证：从访谈走向预售

### 5.1 访谈要问过去行为，不要问「你会不会买」

有效访谈应围绕过去行为，而不是让受访者替你预测未来。建议依次询问：

1. 最近一次遇到这个问题是什么时候？当时具体发生了什么？
2. 你现在如何解决？耗时、费用和效果如何？
3. 这个问题不解决会带来什么损失？优先级为什么高或低？
4. 过去是否为解决它付过钱、投入过人力或更换过供应商？
5. 你理想中的交付结果是什么？什么情况会让你认为没有价值？
6. 如果提供一个范围明确的试用方案，谁能决定，预算和时间窗口是什么？

每次访谈都记录：客户类型、原话、当前替代方案、损失、预算证据、决策人、购买时间、异议和下一步。不要只记录「客户觉得不错」。

### 5.2 建议的预验证门槛

在正式扩大投入前完成：

- 10–15 次有效访谈，且受访者确实属于目标客户，而非泛泛的朋友反馈。
- 至少 3 人愿意进一步查看方案、提供业务资料或预约报价。
- 至少 1 人支付定金或全款。无法收款时，应把原因归类为需求不足、信任不足、价格不足、时机不对、决策链不清或交付不明确，而不是直接得出「市场不存在」。

### 5.3 访谈到成交的漏斗记录

| 环节 | 记录指标 | 目的 |
| --- | --- | --- |
| 目标名单 | 合格潜客数量 | 判断市场是否可触达 |
| 有效触达 | 回复人数和回复率 | 判断信息和渠道是否有效 |
| 访谈 | 完成次数和完成率 | 判断痛点是否真实 |
| 提案 | 提案数和接受率 | 判断 Offer 是否清楚 |
| 报价 | 报价金额和异议 | 判断价格与价值匹配 |
| 付款 | 定金、全款和回款周期 | 判断真实付费意愿 |
| 交付 | 按时完成率、返工率 | 判断交付可控性 |
| 结果 | 客户结果、复购和转介绍 | 判断长期价值 |

## 六、最小可售 Offer（MSO）设计

### 6.1 一页纸启动书

```text
目标客户：
客户所在场景：
最痛且可验证的问题：
不解决该问题的损失：
我提供的最小结果：
具体交付物：
不包含的内容：
客户需要提供的资料：
交付周期：
验收标准：
价格、付款节点和退款边界：
为什么由我来做：
获客渠道和每周动作：
预计直接成本：
预计交付工时：
预计单客毛利：
合规、数据和知识产权风险：
最大投入、最长试跑时间、继续指标：
90 天目标：
```

### 6.2 MSO 的最低标准

一个合格的 MSO 应满足：

1. 客户在 3–10 秒内能听懂服务对象、问题和结果。
2. 交付周期通常不超过 14 天，除非较长周期本身就是客户必要条件。
3. 有明确的输入、输出、验收标准和不包含事项。
4. 必须收费。免费项目只能用于内部练习，不能替代市场验证。
5. 单人可以手动完成，且不依赖客户无法控制的长期配合。
6. 不承诺无法控制的结果，不使用「保证增长」「保证获批」等高风险表述。
7. 对定金、变更、延期、退款、保密、成果归属和售后范围有书面约定。

### 6.3 单位经济模型

至少计算以下四个数字：

- **单客收入：** 客户实际支付金额。
- **直接成本：** 软件、外包、素材、支付手续费、差旅等随订单发生的成本。
- **交付工时成本：** 交付、沟通、修改、售后和收款跟进的总工时 × 个人目标时薪。
- **单客贡献利润：** 单客收入 − 直接成本 − 交付工时成本。

建议同时观察：

```text
单客贡献利润率 = 单客贡献利润 ÷ 单客收入
有效时薪 = 单客贡献利润 ÷ 总投入工时
获客回本周期 = 获客成本 ÷ 单客月贡献利润
```

早期不必追求固定的行业统一阈值，但要做到每单不亏、工时可记录、价格能覆盖风险和机会成本。如果只有收入没有工时记录，无法判断业务是否真的成立。

## 七、14 天最小闭环与后续验证

### 7.1 14 天冲刺计划

| 时间 | 主要动作 | 产出 |
| --- | --- | --- |
| D1–D2 | 选定一个客户人群和一个痛点，写一页纸方案 | 目标客户、价值主张、MSO |
| D3–D4 | 建立 30–50 个合格潜客名单 | 姓名、公司、场景、来源、触达方式 |
| D5–D7 | 完成至少 10 次有效访谈或高质量沟通 | 访谈纪要、异议和需求排序 |
| D8–D9 | 给合格客户发送 3–5 份个性化方案 | 方案、报价、验收标准 |
| D10–D12 | 跟进、处理异议并收取定金或全款 | 付款记录或明确拒绝原因 |
| D13–D14 | 手动交付首单并记录全过程 | 交付物、工时、反馈、SOP 初稿 |

14 天的目标是快速拿到真实证据，不必强求成交。成交周期较长的业务可以把销售周期延长，但必须提前设定阶段性证据，例如获得决策人会议、通过供应商审核或签署付费试点协议。

### 7.2 首 3 个客户的验证标准

建议至少满足以下条件后，才考虑增加投入：

1. 至少 1 个客户真实付款，最好累计获得 2–3 个不同客户的付款证据。
2. 单人独立完成交付，且交付范围没有失控。
3. 单客贡献利润为正，有效时薪没有持续低于个人可接受下限。
4. 客户对结果、过程或交付体验给出具体正面反馈。
5. 至少有 1 个复购、续费、转介绍或明确的后续需求信号。
6. 业务不依赖违法、侵权、未经授权的数据或单一平台。
7. 经过首单后，创业者仍愿意继续承担销售、交付和售后。

### 7.3 失败时的调整顺序

验证失败时，不要同时改变所有变量。建议按以下顺序调整：

1. 先判断是否找对了客户，是否真的触达决策人。
2. 再判断痛点是否足够急，客户当前替代方案是什么。
3. 再调整交付范围和结果表达，减少一次性承诺。
4. 再测试价格、付款节点和试点形式。
5. 最后才考虑彻底更换方向。

最多进行两轮、每轮约 30 天的有记录验证。每轮只能明确改变一到两个关键变量。两轮仍无付款证据时，进入复评、转向或退出，不继续凭意志追加投入。

## 八、合规、合同、数据和质量控制清单

小规模经营同样绕不开风险，这一章把合规、合同、数据和质量控制单独列出。

### 8.1 业务合规

- 核查所在地对行业资质、经营范围、平台规则和广告宣传的要求。
- 对法律、医疗、金融、税务、心理咨询、工程安全等领域，明确是否只能提供辅助性服务，不能替代持证专业意见。
- 不承诺不可控结果，不伪造案例、数据、客户评价或效果。
- 记录客户授权、素材来源、字体、图片、软件和模型的商用许可。

### 8.2 合同与收款

合同或订单确认至少写明：服务范围、交付物、时间、验收、修改次数、付款节点、延期条件、取消和退款、保密、知识产权归属、第三方工具限制、责任边界和争议处理方式。

### 8.3 数据与 AI 使用

- 先确认客户是否允许把资料输入第三方 AI 工具。
- 对个人信息、商业秘密、源代码、财务数据和未公开资料实行最小化收集。
- 建立数据保存期限、访问权限、删除和备份规则。
- AI 生成内容必须经过事实、引用、版权、偏见和安全性检查。
- 不把模型输出当作专业结论，不向客户隐瞒关键人工审核环节。

### 8.4 交付质量

为每个 Offer 建立三张表：

1. **输入清单：** 客户必须提供的资料、格式和截止时间。
2. **质量检查表：** 事实、格式、完整性、合规和验收条件。
3. **交付记录表：** 工时、修改、客户反馈、问题和最终结果。

## 九、经营节奏：从验证转向稳定

### 9.1 每周经营看板

每周只追踪少量关键指标：

| 类别 | 指标 |
| --- | --- |
| 获客 | 新增合格潜客、有效触达、访谈、提案 |
| 成交 | 报价数、定金数、成交率、平均销售周期 |
| 交付 | 按时交付率、实际工时、返工率、客户满意度 |
| 经济 | 收入、直接成本、贡献利润、待收款、现金余额 |
| 客户 | 复购、转介绍、投诉、退款 |
| 个人 | 实际投入时长、睡眠和健康、可持续程度 |

### 9.2 继续、调整、暂停决策表

| 结果 | 决策 |
| --- | --- |
| 连续两个周期有付款，交付可控，单位经济改善 | 继续，逐步标准化和提高价格 |
| 有访谈和提案，但无付款 | 优先调整客户、痛点、信任证明或 Offer，不急于扩张 |
| 有付款但长期亏损或严重超时 | 缩小范围、提高价格、改变交付方式或停止该 Offer |
| 只有单一客户贡献大部分收入 | 先降低集中度，再考虑全职投入 |
| 健康、家庭、现金流明显恶化 | 立即降级为副业、暂停或退出 |
| 两轮有记录验证仍无付款证据 | 返回适配复评或切换替代路径 |

在考虑辞职或全职前，除评分达标外，建议至少具备：可核算的安全垫、连续数周稳定获客行为、多个真实客户付款、可重复交付流程、基本合规方案和明确的退出条件。具体门槛应结合家庭责任、收入波动和业务销售周期设定，不宜使用一个对所有人相同的数字。

## 十、退出与替代路径

### 10.1 立即停止全职投入

出现以下任一情况，应停止全职投入并优先保护健康、家庭、现金流和合规安全：

1. 业务无法合法承接，或风险已经超出个人可控制范围。
2. 健康、家庭或基本生活出现明显恶化。
3. 继续投入需要借高息债、挪用生活费或承担无法承受的损失。

### 10.2 建议停止或转向

满足以下任意两项，建议停止当前方向的全职计划：

- 完成既定修复期仍没有真实付费客户。
- 连续两轮有记录的验证仍无法收款。
- 付款客户的交付长期亏损、超时或引发严重返工。
- 主要获得的是「想象中的市场反馈」，没有决策人和付款证据。
- 每次业务行动都造成持续的身心损耗，且没有能力或认知增长。
- 只喜欢「不上班」，不愿意销售、交付和承担客户责任。

### 10.3 替代路径

| 路径 | 适合情况 |
| --- | --- |
| 自由职业 | 有单项技能，愿意按项目售卖时间，但暂不经营完整业务 |
| 合伙创业 | 专业能力强，但销售、运营或资金存在明显互补需求 |
| 加入早期团队 | 想体验创业，但暂时不想独自承担全部现金流风险 |
| 内部创业 | 已有平台、客户、品牌或合规资源可以复用 |
| 副业测试 | 方向有兴趣，但需要先保护主业和家庭现金流 |
| 回到专业岗位 | 先积累案例、行业资源和资金，再择机重启 |

退出不是失败。应保留一份复盘：测试过的客户、实际报价、付款证据、拒绝原因、交付工时、单位经济、合规问题和下一次不再重复的假设。

## 十一、最终执行清单

在进入下一阶段前，逐项回答「是 / 否」，并保存证据：

- [ ] 生存、家庭、健康和合规红线检查已完成。
- [ ] 最大投入、最长试跑时间和最低继续指标已写下。
- [ ] 适配度评分每一项都附有证据，而不只是主观印象。
- [ ] 能明确说出一个具体客户、一种场景和一个可衡量结果。
- [ ] 已完成至少 10 次目标客户访谈，并记录原话和购买行为。
- [ ] 手上有一份范围明确、周期清楚、必须收费的 MSO。
- [ ] 直接成本、交付工时、贡献利润和有效时薪都已算过。
- [ ] 合同、验收、退款、知识产权和数据使用边界都已写明。
- [ ] 至少完成过一次真实收款和完整交付。
- [ ] 继续、调整、暂停和退出的条件都已明确。

只有当「真实付款 + 可控交付 + 单位经济为正 + 风险可控」同时出现时，才把方向视为初步验证成功。

## 十二、两层闸门：通用判断 + 模式专属指标

前面的五道闸门可以覆盖大多数 OPC，但不同模式需要盯的结果指标并不相同：独立开发者看留存，网文作者看追读和持续产能，独立站看售后后利润，专业服务看回款和交付工时。因此建议采用两层结构：

第一层是所有 OPC 通用的五道闸门。它判断生存安全、基本能力、真实需求、交易闭环和经济可持续性。

**第二层是模式专属指标。** 它判断某一种业务模式最关键的行为证据、经营指标和模式风险。第二层不能替代第一层；任何模式都必须先满足合规和止损要求。

### 12.1 第一层：所有 OPC 通用的五道闸门

| 闸门 | 通用判断问题 | 最低证据 |
| --- | --- | --- |
| 1. 生存与合规 | 能否在不破坏生活、健康和家庭责任的情况下试跑？业务是否可合法开展？ | 安全垫或稳定现金流、风险清单、资质与平台规则初查 |
| 2. 能力与资源 | 能否独立完成该模式的关键工作？ | 能力证据、时间安排、工具和供应商方案 |
| 3. 问题与客户 | 是否有明确人群、场景和足够强的需求？ | 目标客户定义、行为访谈、搜索或内容数据、替代方案 |
| 4. 付款与交付 | 是否有人真实付款，且能完成可验收的交付？ | 付款、订单、订阅、签约、稿酬或平台结算记录，以及交付结果 |
| 5. 单位经济与可持续性 | 扣除直接成本、获客、时间、售后和风险后，是否值得继续？ | 毛利或贡献利润、投入工时、留存/复购、现金流和个人耐久度 |

**通用通过条件：** 只有一项达标不算通过。真实交易证据、可控交付、经济核算和可接受风险需要同时出现；「上线」「涨粉」「有访问量」「有订单」都算不上业务已经验证成功。

| 服务 + 数字产品 | 先做项目，再把方法沉淀为模板、课程或工具 |
| 个人品牌 + 授权 | 内容影响力结合出版、演讲、品牌合作和 IP 授权 |
| AI 增强型个人业务 | 以个人判断和客户信任为核心，AI 提升研究和交付效率 |
| 多收入组合 | 服务、订阅、广告、联盟、授权和数字产品组合经营 |

以上目录覆盖了常见的服务型、软件型、内容型、数字资产型、电商型、出海型、社群型和混合型 OPC，是选指标用的分类，不是法律或行业分类。如果某个业务同时属于多个类别，应选择主要收入来源和主要风险来源作为第一模式，再叠加其他模式的指标。

### 12.3 第二层：各模式的专属指标

下表给出各类模式的核心验证指标。指标分为四组：**行为证据**用于判断是否真的有人使用或购买；**经营指标**用于判断效率和质量；**经济指标**用于判断是否赚钱；**主要风险**用于判断是否可能因平台、合规或交付问题失控。

| 模式大类 | 核心验证信号 | 必看经营指标 | 单位经济或持续性指标 | 主要专属风险 |
| --- | --- | --- | --- | --- |
| 专业服务、顾问、自由职业 | 多个客户签约并回款 | 报价接受率、交付准时率、修改次数、客户满意度 | 单客贡献利润、有效时薪、回款周期、复购/转介绍率 | 范围蔓延、坏账、责任边界、过度依赖个人时间 |
| 产品化服务、代运营、托管 | 客户购买标准化套餐并续费 | 交付周期、SOP 覆盖率、工时偏差、客户留存 | 套餐毛利、月度经常性收入、客户流失率 | 服务承诺失控、客户数据、平台授权、结果不可控 |
| 教练、培训、陪跑 | 学员付款并完成关键任务 | 到课率、完成率、作业提交率、满意度 | 每位学员贡献利润、续费率、转介绍率 | 夸大效果、资质边界、学员结果不可控 |
| 招聘、撮合、经纪 | 撮合成功并产生佣金 | 合格线索率、匹配率、成交周期、履约率 | 每单佣金、获客成本、退款/纠纷率 | 信息真实性、隐私、佣金争议、平台规则 |
| 独立开发、Micro-SaaS、AI 应用 | 用户完成核心动作并持续使用 | 激活率、留存率、付费转化率、故障率 | MRR、ARPU、服务器/API 成本、LTV/CAC | 数据安全、模型错误、平台/API 依赖、技术债 |
| API、开发者工具、插件 | 开发者接入并在真实项目中使用 | 激活、调用量、错误率、文档转化率、留存 | 每调用成本、订阅收入、支持工时、毛利 | 兼容性、供应商变更、滥用、开源许可证 |
| 数据产品、数据库、情报服务 | 客户订阅并将数据用于决策 | 数据更新及时率、准确率、使用频率、续费率 | 每客户数据服务成本、订阅毛利、流失率 | 数据来源、版权、隐私、准确性责任 |
| 独立游戏、互动产品 | 玩家完成核心体验并回访或付费 | 次日/七日留存、完成率、崩溃率、评价 | 每用户收入、内容更新成本、退款率 | 平台审核、版权、内容合规、上线后维护 |
| 网文、剧本、漫画作者 | 读者持续追读并产生订阅/稿酬/授权 | 更新稳定性、收藏率、追读率、完读率、评论质量 | 每千字收入、单位创作时薪、单作品回收期 | 版权合同、平台依赖、收入周期、创作健康 |
| 新媒体账号、个人品牌 | 目标受众持续关注并产生商业行为 | 完读/观看时长、收藏转发、私信、目标粉丝占比 | 每条内容工时、每千次有效触达收入、商业转化率 | 平台依赖、广告合规、素材版权、流量波动 |
| 付费通讯、研究报告、专栏 | 读者付费订阅并持续打开和续费 | 打开率、阅读率、点击率、退订率、续费率 | 每订阅者贡献利润、内容生产时薪、收入集中度 | 引用准确性、版权、信息责任、邮件合规 |
| 课程、训练营、知识产品 | 用户付费、完成学习并获得可感知结果 | 注册转化、到课率、完成率、退款率、学员反馈 | 每学员交付成本、续费/升级率、客服工时 | 课程效果表述、版权、个人信息、平台分成 |
| 会员社群、问答、专家网络 | 会员持续参与并续费 | 活跃率、提问率、回答时效、留存率、内容产出 | 每会员月贡献利润、管理员工时、流失率 | 社群质量、内容责任、骚扰、隐私和退款 |
| 播客、音频、视频节目 | 稳定受众增长并完成订阅/赞助/广告 | 完播率、回访率、订阅率、赞助询盘、发布稳定性 | 每期制作工时、每千次有效播放收入、赞助毛利 | 音乐和素材版权、广告披露、平台依赖 |
| 模板、电子书、资料包、数字下载 | 用户购买、下载并低退款 | 页面转化率、下载成功率、退款率、评价 | 单份边际成本、广告后利润、自然流量占比 | 版权、盗版、内容过时、平台封禁 |
| 素材、字体、图标、音频、3D 资产 | 客户购买许可并实际使用 | 授权数量、下载量、复购率、投诉率 | 每资产制作工时、授权收入、维护成本 | 商用许可、模型训练来源、侵权和重复售卖 |

| 预售、众筹、按需生产、POD | 达到订单门槛并按承诺交付 | 预售转化、交付延期率、缺陷率、退款率 | 预付款现金流、每件贡献利润、生产损耗 | 交付承诺、质量、消费者退款和现金流错配 |

| 资源订阅、机会情报、招标/招聘信息 | 用户因信息产生行动并续订 | 信息新鲜度、命中率、打开率、续费率 | 每订阅者服务成本、订阅毛利、流失率 | 信息准确性、数据来源、隐私、责任边界 |
| 众包、调研、数据标注、体验测试 | 客户重复购买且参与者能稳定交付 | 样本合格率、完成率、返工率、交付周期 | 每项目毛利、参与者成本、客户复购 | 个人信息、样本偏差、劳务和付款合规 |

### 12.4 如何使用模式专属指标

不要试图一次追踪表中的全部指标。每个 OPC 模式选择以下三组指标即可：

1. **一个北极星指标：** 最能代表客户持续获得价值的指标，例如付费用户留存、签收订单、有效订阅、完成交付或读者追读。
2. **两个过程指标：** 能解释北极星指标变化的动作，例如有效访谈、激活率、提案接受率、内容发布稳定性或发货及时率。
3. **两个安全指标：** 防止表面增长掩盖损失的指标，例如贡献利润、退款率、现金流、投诉率、数据事件或有效时薪。

推荐记录格式如下：

```text
我的 OPC 模式：
主要收入来源：
第一层五道闸门当前状态：
北极星指标：
过程指标 1：
过程指标 2：
安全指标 1：
安全指标 2：
本周期目标：
继续、调整或暂停条件：
数据来源和复盘日期：
```

### 12.5 五类常被误判的「伪验证信号」

| 表面信号 | 为什么不足 | 应替换为 |
| --- | --- | --- |
| 产品上线 | 上线不代表有人需要 | 核心功能使用、留存和付费 |
| 粉丝增长 | 粉丝可能不是目标客户 | 目标受众占比、商业转化和复购 |
| 文章有阅读量 | 阅读不代表愿意付费或持续追读 | 追读、订阅、稿费和版权收入 |
| 独立站有订单 | 订单可能被广告、退款和拒付吞噬 | 签收后的贡献利润和复购 |
| 无货源电商有销售额 | 销售额没有扣除物流、售后和平台风险 | 售后后利润、妥投率和退款/拒付率 |

**最终规则：** 第一层判断这项尝试能否安全、合规、可持续地运行；第二层判断这种具体模式是否出现了它应有的真实增长信号。两层同时通过，才适合扩大投入或考虑全职化。
