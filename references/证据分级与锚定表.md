# 证据分级与评分锚定表

> **随引擎 v0.6.1 更新** · 2026-09-15

宿主提问时的口径依据。打分前必须先问证据，没有证据就打不高。这是第三章 3.1 的硬规则，由 `gate.py` 代码执行。

---

## 一、四类信号的强度分级

出处：第一章末段、第五章 5.2。

| 级 | 名称 | 形态 | 算已验证吗 | 宿主追问 |
|---|---|---|---|---|
| 0 | 口头兴趣 | "有人说感兴趣" | 否 | "他愿意留下联系方式吗？" |
| 1 | 弱信号 | 愿意留下联系方式 | 否 | "他愿意给业务资料或预约一次沟通吗？" |
| 2 | 中等信号 | 愿意预约并提供业务信息 | 否 | "谁做决定？预算和时间窗口是什么？" |
| 3 | **强验证** | **支付定金或全款** | **是** | 记录金额、时间、凭证 |

规则：没有付款就不称"已验证"。级别 2 及以下只能表述为"需求信号"，不能写进"已通过闸门 4"。

无法收款时按第五章 5.2 归因，不要直接得出"市场不存在"：
需求不足 / 信任不足 / 价格不足 / 时机不对 / 决策链不清 / 交付不明确。

## 二、0–5 分锚定（第三章 3.1 通用档）

| 分 | 含义 |
|---|---|
| 0 | 没有能力、资源或行为证据 |
| 1–2 | 有兴趣或零散经验，但不能稳定复现 |
| 3 | 曾经完成过，或正在按计划练习 |
| 4 | 能独立稳定完成，并有案例、回款或可验证记录 |
| 5 | 已形成可复用方法，能够持续产生结果或教会他人 |

硬规则：只有"我觉得我可以"而没有事实记录时，最高只能打 2 分。引擎对 `evidence` 为空的项目一律封顶 2 分，无论用户报了几分。

## 三、16 项的 1 分 / 5 分锚定话术

宿主逐项提问时，先念 1 分和 5 分锚定，再让用户报分；用户报分后**必须追问证据**。

### 动机与耐久度

| 项（权重） | 1 分锚定 | 5 分锚定 | 证据形态 |
|---|---|---|---|
| 主动选择经营业务，而非仅为逃避职场（5） | 主要动机是"不想上班了" | 有明确的客户与结果承诺，且能说清为什么是这件事 | 原话、时间线 |
| 接受不确定性，并在无外部监督时推进（5） | 有人催才动 | 连续数月自主推进并留有记录 | 推进日志 |
| 能长期承担销售、交付、售后和复盘（5） | 只想做交付环节 | 完整跑过多轮，且愿意继续跑 | 全流程记录 |
| 在连续被拒绝时仍能调整而非停摆（5） | 被拒几次就停 | 有被拒后调整方案的具体记录 | 被拒记录 + 调整动作 |

### 能力闭环

| 项（权重） | 1 分锚定 | 5 分锚定 | 证据形态 |
|---|---|---|---|
| 曾独立完成项目并成功收款（10） | 只做过无偿帮忙 | 多笔独立回款，且有交付记录 | 合同 / 回款凭证 |
| 具备可对外售卖的专业能力或可验证成果（8） | 自认为会，无对外成果 | 有作品集、案例库或第三方认可 | 作品集 / 案例 |
| 能判断业务边界与不适合服务的客户（6） | 什么单都想接 | 有不服务清单与责任边界说明 | 不服务清单 |
| 能学习并执行获客、报价和谈判（6） | 完全没试过获客 | 有稳定触达记录与报价谈判案例 | 触达记录 / 报价单 |

### 资源与风险

| 项（权重） | 1 分锚定 | 5 分锚定 | 证据形态 |
|---|---|---|---|
| 有可核算的现金安全垫或稳定现金流（8） | 无核算，说不清能撑多久 | 安全垫月数 ≥ 个人目标，且有账目 | 现金 ÷ 月必要支出 |
| 每周可稳定投入时间，家庭责任已安排（6） | 时间完全不可控 | 有固定时段，且家人已知情并配合 | 周排期表 |
| 了解基本合同、财税、知识产权和数据安全要求（6） | 完全没概念 | 有合同模板、风险清单和处理方案 | 风险清单 |

### 市场证据

| 项（权重） | 1 分锚定 | 5 分锚定 | 证据形态 |
|---|---|---|---|
| 已有付费客户、定金或可核实的购买行为（10） | 完全没有 | 多个不同客户的付款证据 | 付款记录 |
| 能清晰描述目标客户和高频痛点（5） | 只能说"中小企业" | 能说出 5 个具体客户 / 账号与其原话 | 客户名单 + 原话 |
| 已有低成本、可重复触达客户的渠道（5） | 完全没有渠道 | 有渠道、有回复率数据、成本可控 | 触达记录 |

### OPC 结构

| 项（权重） | 1 分锚定 | 5 分锚定 | 证据形态 |
|---|---|---|---|
| 交付可以标准化，AI 能提高效率而非替代责任（5） | 每次都从头做 | 有 SOP / 模板，AI 只做整理与初稿，交付责任仍由本人承担 | SOP、模板 |
| 不依赖大团队、重资产或长期垫资（5） | 需要垫资或多人 | 单人可完成，零重资产 | 交付清单 |

## 四、伪验证信号 ↔ 可验证指标（双向映射）

出处：第十二章 12.5。左列出现即拦截，右列才是该问的东西。

| 表面信号（拦截） | 为什么不足 | 替换为（追问这个） |
|---|---|---|
| 产品上线 | 上线不代表有人需要 | 核心功能使用、留存和付费 |
| 粉丝增长 | 粉丝可能不是目标客户 | 目标受众占比、商业转化和复购 |
| 文章有阅读量 | 阅读不代表愿意付费或持续追读 | 追读、订阅、稿费和版权收入 |
| 独立站有订单 | 订单可能被广告、退款和拒付吞噬 | 签收后的贡献利润和复购 |
| 无货源电商有销售额 | 销售额没扣物流、售后和平台风险 | 售后后利润、妥投率和退款/拒付率 |

通用拦截句（宿主可直接用）：
> "这个数字本身还不能说明方向成立。按方法论，我需要换成另一个问题：___ 是多少？"

## 五、单位经济的必填四数字（第六章 6.3）

| 数字 | 算法 |
|---|---|
| 单客收入 | 客户实际支付金额 |
| 直接成本 | 软件、外包、素材、支付手续费、差旅等随订单发生的成本 |
| 交付工时成本 | （交付 + 沟通 + 修改 + 售后 + 收款跟进）小时 × 个人目标时薪 |
| 单客贡献利润 | 单客收入 − 直接成本 − 交付工时成本 |

派生：贡献利润率 = 贡献利润 ÷ 单客收入；有效时薪 = 贡献利润 ÷ 总投入工时；获客回本周期 = 获客成本 ÷ 单客月贡献利润。

拒答规则：有收入但无工时记录时，引擎输出 `INCOMPLETE`，不给数字。只有收入没有工时，无法判断业务是否真的成立。

## 六、方向评分卡 9 项锚定（第四章 4.2）

每个候选方向都要打这 9 项。其中客户可触达性 / 交付可控性 / 合规与依赖风险三项低于 3 分，方向直接不合格，其他项再高也不补。

| 项（权重） | 1 分锚定 | 5 分锚定 | 硬约束 |
|---|---|---:|---|
| 痛点和损失强度（20%） | 客户只是"有点不方便" | 不解决就损失收入、踩合规红线或大量浪费时间 | |
| 已有付费证据（20%） | 没人为相似方案花过钱 | 已有客户付费，或明确愿意付定金 | |
| 客户可触达性（15%） | 不知道去哪找客户 | 有低成本、可重复的触达路径，并已跑通 | **是** |
| 结果可衡量性（10%） | 交付完说不清好坏 | 能用时间、成本、收入、转化率或风险指标验收 | |
| 交付可控性（10%） | 依赖不可控的第三方或客户长期配合 | 单人能在约定时间内独立完成 | **是** |
| 单位经济（10%） | 扣掉成本和工时是亏的 | 有明确且合理的毛利 | |
| 复购与转介绍（5%） | 一次性需求，做完就断 | 需求重复出现，客户容易带来同类客户 | |
| 合规与依赖风险（5%） | 需要拿不到的资质，或强依赖单一平台 | 无资质门槛，不绑定单一平台或单一客户 | **是** |
| 个人耐久度（5%） | 做三个月就想跑 | 愿意持续做 2–3 年 | |

两个常见误用：
- 用"个人耐久度"高分去救一个没人付钱的方向。耐久度只是约束条件，替代不了市场需求。
- 方向命名只写宽泛能力标签（"AI 咨询""代运营""内容创作"）。正确写法是"客户人群 + 场景 + 结果 + 交付形式"，引擎会对模糊标签出提示。

## 七、MSO 七条最低标准自检（第六章 6.2）

引擎逐条自动校验，宿主提问时按这条清单收口。

| # | 标准 | 常见不通过原因 |
|---|---|---|
| 1 | 3–10 秒听懂服务对象、问题和结果 | 目标客户 / 最痛问题 / 最小结果 三项没齐 |
| 2 | 交付周期 ≤ 14 天 | 未填周期，或周期靠"客户配合"才成立 |
| 3 | 有输入、输出、验收标准和不包含事项 | "不包含的内容"最常被跳过，而它一缺，交付必然失控 |
| 4 | **必须收费** | 填了 0 或想"先免费试一单"。免费只能内部练习 |
| 5 | 单人可手动完成，不依赖客户长期配合 | 未填预计交付工时，无法判断可控性 |
| 6 | 不承诺无法控制的结果 | 出现"保证 / 确保 / 一定能 / 必然 / 100% / 零风险 / 包过 / 包成功 / 稳赚" |
| 7 | 七项书面约定齐备 | 定金 / 变更 / 延期 / 退款 / 保密 / 成果归属 / 售后 有缺项 |

> 第 6 条按硬红线处理：绝对化表述一出现就判不通过。改法是把"保证增长 30%"改成对客户结果的中性描述，例如"按 20 条模板直接复用，减少重复客服工时"。

## 八、首 3 个客户与止损监控

首 3 个客户（第七章 7.2）：真实付款 ≥1 → 单人独立交付不失控 → 单客贡献利润为正 → 客户有具体正面反馈 → 有 1 个复购/转介绍信号 → 不依赖违法或单一平台 → 做完首单仍愿意继续承担销售、交付、售后。

止损监控（第十章 + 第七章 7.3）：

| 触发 | 判定 |
|---|---|
| 业务无法合法承接 / 健康家庭明显恶化 / 需借高息债或挪用生活费 | `EXIT_NOW` 立即停止全职投入 |
| 上述"建议停止或转向"条件命中任意 **2 项** | `STOP` |
| 已完成 2 轮验证且零付款记录 | `EXIT` |
| 现金投入或试跑时间超限 | `PAUSE` |
| 已有付款记录，但尚无复购与转介绍 | `KEEP` |
| 零付款且未达上限 | `ADJUST`（按调整顺序改 1–2 个变量） |

调整顺序不可跳步：客户对不对 → 痛点急不急 → 交付范围与结果表达 → 价格与付款节点，最后才换方向。
每轮最多改 2 个变量，最多 2 轮、每轮约 30 天。失败后的 6 条替代路径（自由职业 / 合伙创业 / 加入早期团队 / 内部创业 / 副业测试 / 回到专业岗位）由引擎在 `stop` 输出中给出，**只给路径，不替用户选择**。
