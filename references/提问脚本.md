# 提问脚本（宿主直接照读）

> **随引擎 v0.6.0 更新** · 2026-09-15

原则：一次只问一条，等回答再问下一条。不打分就走完流程，等于没做。

---

## 第 0 步 · 开场

> 接下来我会按五道闸门问你一批问题，大概 15–25 分钟，最后给你一份 HTML 决策书。
> 先说清一件事：这套流程不会给出"可以辞职"的结论，它的作用是找出你还缺哪些证据，以及现在还差多远。
> 过程中你可以随时说"跳过"或"这个我不想答"。
>
> 五道闸门属于第一层，所有一人公司通用。第一层放行之后，我们才会进入第二层，确认你具体属于哪种 OPC 模式、该盯哪五个指标。第二层不能替代第一层，两层都过了才谈扩大投入。
>
> 最后一点：我只依据你现在说的话来判断，不会引用你的历史会话或记忆画像。如果你想拿以前做过的某个项目来验证，请你自己说出来，我不会替你翻。

## 第 1 步 · 闸门 1：生存与合规

### 1.1 硬红线（逐条问，必须一条一条来）

> 下面的问题请一个个回答，答"是"我就记下，因为任何一条成立，我们就只谈低成本副业测试。

1. 你现在有没有经过核算的生活费安全垫？如果今天起没有新收入，能撑几个月？
2. 这件事需要强制资质、许可、备案或执业资格吗？你现在能合法取得，或者有合规主体能承接吗？
3. 这个业务会不会碰到人身安全、重大财产、个人敏感信息、未成年人信息、版权或商业秘密？你有没有对应的风控方案？
4. 你的健康、心理状态、照护责任或家庭关系，现在是明显失衡的吗？
5. 全职做这件事，会不会导致高息负债、基本生活中断、家庭义务没法履行，或者最坏情况你承担不起？
6. 获客方式会不会依赖违法手段、虚假宣传、侵权素材、未授权数据，或者规避平台规则？

> 补充问：可动用现金具体多少？每月最低必要支出多少？你希望的安全垫目标是多少个月？
> （引擎按"可动用现金 ÷ 每月最低必要支出"算月数，不机械套 6–12 个月。）

### 1.2 软风险（逐条问，命中就记）

> 下面这些不一定会否决，但命中一条就会写进修复计划。

1. 你有没有独立完整跑过"获客—报价—签约—交付—收款—售后"这一整条？
2. 你对销售、沟通、谈判、被拒绝，是极度排斥吗？
3. 你想做这件事，主要动机是逃离职场，还是真的愿意长期承担客户结果？
4. 你愿意做客户选择、定价、取舍和业务判断，还是只想执行任务？
5. 你跟你说的那类客户，有过真实接触吗？还是主要靠想象判断？
6. 这个方向是不是只靠一个平台、一个客户或一个工具？
7. 合同、发票、税务、知识产权、数据安全、售后边界，你有基本认识吗？

### 1.3 止损三数字（三项都必须写下来）

> 在开始任何付费测试前，先写下三个数字：

1. 最大现金投入：在不影响生活的前提下最多投多少？
2. 最长试跑时间：到复盘点前最多投入多久？
3. 最低结果：达到什么结果你才继续？

> 不要在拿到答案前往下走。缺任意一项，引擎会判 `INCOMPLETE`，不出适配度结论。

## 第 2 步 · 闸门 2：适配度评分

> 16 项，我一项一项问。每项先给你 1 分和 5 分的样子，你报 1–5，然后我会追问证据。
> 没有具体案例或记录的话，这一项按方法论最高只算 2 分。这条规则对所有人一样，不是针对你。

逐项念锚定（见 `证据分级与锚定表.md` 第三节），每项固定追问：

> "有什么具体的案例、记录、回款或凭证能对得上？"

用户答"我觉得我可以 / 应该没问题" → 追问：

> "有没有发生过一次？大概什么时候？当时的结果是什么？"
> 仍然没有 → 记 `evidence` 为空，不纠缠。

用户明确说不知道 / 不想答 → 该项直接不填，引擎标"未评估"。

## 第 3 步 · 闸门 3：方向选择 + 预验证漏斗

> 顺序不能颠倒：先出方向，再谈客户。我不会问你"觉得哪个赛道火"，热度不是评分项。

### 3.1 方向生成（从四类证据出发，产出 3–5 个候选）

1. 过去 3–5 年里，你反复做过、做出过结果、而且不完全依赖某一个雇主的事情是什么？
2. 别人反复来找你咨询、请你代办、或者愿意花钱让你帮他们省时间的，是什么事？
3. 你接触过的行业里，客户已经在花钱解决、但现有方案做得不好的问题是什么？
4. 你能在 14 天内做完最小交付，并且能说清验收标准的事情是什么？

> 命名要求：写成"客户人群 + 场景 + 结果 + 交付形式"。
> 不合格："AI 咨询" / "代运营" / "内容创作"
> 合格："帮跨境小卖家在 7 天内整理客服知识库和回复模板，减少重复客服工时"
> 说成光秃秃的能力标签，引擎会给你标"命名待改"。

每个方向记 `basis`：`past_results` / `referrals` / `market_gap` / `fast_deliverable`。

### 3.2 方向评分卡（每个方向 9 项，1–5 分，每项要事实依据）

按权重念，权重高的先问：

| 顺序 | 评分项 | 权重 | 问法 |
|---|---|---:|---|
| 1 | 痛点和损失强度 | 20% | 不解决，客户会损失收入、增加成本、踩合规红线，还是大量浪费时间？ |
| 2 | 已有付费证据 | 20% | 客户有没有已经为相似方案花过钱？愿不愿意付定金？ |
| 3 | 客户可触达性 | 15% | 你能不能低成本找到这批人，并持续触达？ |
| 4 | 结果可衡量性 | 10% | 交付后能用时间、成本、收入、转化率或风险指标验收吗？ |
| 5 | 交付可控性 | 10% | 你一个人能在约定时间内做完吗？依赖不可控的第三方吗？ |
| 6 | 单位经济 | 10% | 扣掉直接成本和工时，还有合理毛利吗？ |
| 7 | 复购与转介绍 | 5% | 需求会重复出现吗？客户容易介绍同类客户吗？ |
| 8 | 合规与依赖风险 | 5% | 有资质、数据、平台、版权或单一客户风险吗？ |
| 9 | 个人耐久度 | 5% | 你愿意持续做至少 2–3 年吗？ |

> 三项硬约束先看：客户可触达性 / 交付可控性 / 合规与依赖风险。任一项低于 3 分，这个方向直接不合格，不要用其他项的高分去补。
> 个人耐久度只是约束条件，分高也救不了一个没人付钱的方向。

先跑 `direct`，把不合格方向当场划掉，别带着它往下走。

### 3.3 预验证门槛 + 漏斗

> 访谈要问过去发生过什么，不要问"你会不会买"，也不要让人替你预测未来。

访谈六问（每次都要记原话）：

1. 你最近一次遇到这个问题是什么时候？当时具体发生了什么？
2. 你现在怎么解决的？花了多少时间、多少钱？效果怎么样？
3. 这个问题不解决，会带来什么损失？对你来说优先级高不高？
4. 你过去为解决它，付过钱、投过人，或者换过供应商吗？
5. 你理想中的交付结果是什么？什么情况会让你觉得这东西没价值？
6. 如果给你一个范围明确的试用方案，谁做决定？预算和时间窗口是什么？

记录要求：客户类型、原话、当前替代方案、损失、预算证据、决策人、购买时间、异议、下一步。
只记"客户觉得不错"，等于没记。

三个门槛数字（`funnel` 用）：

| 项目 | 门槛 | 备注 |
|---|---|---|
| 有效访谈 | ≥ 10 次（建议 15） | 受访者必须是目标客户，不是泛泛的朋友 |
| 愿意进一步 | ≥ 3 人 | 愿意看方案 / 给资料 / 约报价 |
| 支付定金或全款 | ≥ 1 人 | **没有付款就不能说方向已验证** |

漏斗八环节：目标名单 → 有效触达 → 访谈 → 提案 → 报价 → 付款 → 交付 → 结果。

> 收不到钱要先归因，不要急着下结论。从"需求不足 / 信任不足 / 价格不足 / 时机不对 / 决策链不清 / 交付不明确"里选，不要直接说"市场不存在"。

## 第 4 步 · 闸门 4：MSO + 首 3 个客户

### 4.1 一页纸启动书（19 项，逐项问，缺项会被标出来）

> 现在把这个 Offer 写成一页纸。我一项一项问，写不出来就先留空，留空比瞎填好。

1. 目标客户是谁？（要具体到人群特征，不是"所有做生意的人"）
2. 客户在什么场景下会遇到这个问题？
3. 最痛、而且能验证的问题是什么？
4. 不解决这个问题，他的损失是什么？
5. 你提供的最小结果是什么？
6. 具体交付物是什么？
7. 不包含什么？（这一项最常被跳过，但没有它交付一定失控）
8. 客户需要提供什么资料？
9. 交付周期多少天？
10. 验收标准是什么？
11. 价格多少？付款节点、退款边界怎么定？
12. 为什么由你来做？
13. 获客渠道和每周动作是什么？
14. 预计直接成本多少？
15. 预计交付工时多少小时？
16. 预计单客毛利多少？
17. 合规、数据、知识产权风险有哪些？
18. 最大投入、最长试跑时间、继续指标分别是多少？
19. 90 天目标是什么？

### 4.2 MSO 七条最低标准（自动校验）

1. 客户能在 3–10 秒内听懂服务对象、问题和结果（目标客户 / 最痛问题 / 最小结果 三项齐备）
2. 交付周期不超过 14 天（除非长周期本身就是客户必要条件）
3. 有明确的输入、输出、验收标准和不包含事项
4. **必须收费**——价格为 0 直接不通过。免费项目只能内部练习，不能替代市场验证
5. 单人可以手动完成，不依赖客户无法控制的长期配合
6. 不承诺无法控制的结果。"保证增长 30%""确保获批""一定能""100%""零风险"这类词一出现，直接判不通过
7. 定金、变更、延期、退款、保密、成果归属、售后范围，七项都要有书面约定

### 4.3 首 3 个客户的验证标准（7 条）

1. 至少 1 个客户真实付款，最好有 2–3 个不同客户的付款证据
2. 单人独立完成交付，交付范围没有失控
3. 单客贡献利润为正，有效时薪没有持续低于你的下限
4. 客户对结果、过程或交付体验，给出过具体正面反馈
5. 至少有 1 个复购、续费、转介绍或明确的后续需求信号
6. 业务不依赖违法、侵权、未授权数据或单一平台
7. 做完首单之后，你还愿意继续承担销售、交付和售后

### 4.4 试跑跟踪（`tracking`）

> 每次调整都记下来：这一轮你改了什么、有没有收到钱。

- 目前已投入现金多少？上限多少？（`cash_spent` / `cash_limit`）
- 已经试跑几周？上限几周？（`weeks_elapsed` / `weeks_limit`）
- 第几轮？这一轮改变了哪几个变量？（每轮最多 2 个）
- 这一轮有没有收到付款？

调整顺序（不许一次全改）：先看客户找对没有，再看痛点够不够急，然后调交付范围和结果表达，再测价格与付款节点，最后才考虑换方向。

> 最多两轮，每轮约 30 天。两轮仍无付款记录，就进入复评、转向或退出，不继续凭意志追加投入。
> 出现这些情况要立刻停下来：业务无法合法承接 / 健康、家庭明显恶化 / 需要借高息债或挪用生活费。

## 第 5 步 · 闸门 5 前置：单位经济

> 现在有没有已经成交的单子？一个都没有也可以，如实说。

有订单时逐单问：

1. 这笔客户实际付了多少？
2. 随这笔订单发生的直接成本有多少？（软件、外包、素材、手续费、差旅）
3. 从沟通到最后收款，一共花了多少小时？
4. 你自己的目标时薪是多少？
5. 获客成本大概多少？这个客户每月能带来的贡献利润多少？（用来算回本周期）

无订单时：

> 那单位经济这块先留空。等你有了第一笔真实订单，我们回来把它填上。有收入没有工时记录的话，是算不出来的。

## 第 6 步 · 信号真实性检查

> 你刚才提到的进展里，如果有下面这些说法，我需要换一个问法。

逐条对照并拦截：

| 用户可能说 | 拦截并改问 |
|---|---|
| "产品已经上线了" | "有多少人用了核心功能？次日和七日留存是多少？有多少付费了？" |
| "粉丝涨到 X 千了" | "其中目标客户占多少？转化了多少？复购了没有？" |
| "阅读量还不错" | "追读率多少？订阅了多少？有稿费或版权收入吗？" |
| "独立站有订单了" | "订单里签收率多少？扣掉广告、退款和拒付之后的贡献利润是多少？复购呢？" |
| "有销售额 / GMV" | "扣掉物流、售后和平台风险之后，售后后利润是多少？妥投率和退款/拒付率呢？" |

拦截句模板：

> "这个数字本身还不能说明方向成立。按方法论，我需要换成另一个问题：___ 是多少？"

信号只有第 4 级（真实付款）才算强验证，前三级分别是口头兴趣、留联系方式、预约并给资料。

## 第 7 步 · 第二层（**仅在第一层放行后**）

> 前提：只有第一层结论是 `READY_FOR_LAYER2` 才进这一步。不是的话直接跳到第 8 步收尾，不要提第二层。
> 第二层不能替代第一层，两层是 AND。

### 7.1 先定模式（必须先问收入来源）

第一个问题是固定的，不要换成别的：

> 「你的钱主要从哪来？」是客户按项目付款、按订阅付费、平台佣金、卖数字产品，还是广告与赞助？

> 为什么先问这个：一个业务可能同时属于多个类别，方法论规定按主要收入来源 + 主要风险来源选第一模式，
> 其余只作为叠加模式取指标。方向名称不算依据：「帮客户整理知识库与模板」里有"模板"两个字，
> 不意味着这是卖模板的生意，它可能是产品化服务。所以只给方向名的话引擎会回问，不会替你猜。

再补一问：

> 这个模式里，你最担心哪一类风险？（交付范围、平台规则、版权、合规、现金流、个人时间……）

然后跑：

```bash
python3 scripts/gate.py modes --config opc_input.json
```

三种返回要区别对待：

| 返回 | 含义 | 你要做什么 |
|---|---|---|
| `BLOCKED_ORDER`（rc=4） | 没有合格候选方向 | 说明模式目录不能反用于选题；回去做第 3 步 |
| `NEEDS_INPUT` | 只给了方向名，缺收入来源 | 把 7.1 的问题问出来，补 `layer2.revenue_source` |
| `RESOLVED` | 归类成功 | 核对模式名；`ambiguous=true` 时必须跟用户确认 |

> 归类结果里有 `confidence`：`high`（有收入来源）/ `low`（只凭方向名推断）/
> `none`（不足以归类）。`low` 也要跟用户确认一次。

### 7.2 挑指标：1 + 2 + 2（不要让用户自己想）

> 不要试图追踪整张指标表。你的模式只需要五个指标：一个北极星、两个过程、两个安全。

引擎会给出候选池，念给用户听，让他选：

- **北极星指标 1 个**——最能代表客户持续获得价值的那个。候选来自该模式的「核心验证信号」，需要量化成指标。
- **过程指标 2 个**——能解释北极星变化的动作。候选来自该模式的「必看经营指标」。
- **安全指标 2 个**——防止表面增长掩盖损失。候选来自「单位经济/持续性」+「主要专属风险」。

追问口径：

> 「这五个指标，你现在能拿到数据吗？数据从哪来？」

拿不到数据的指标要当场换掉，记不了的指标等于没有。

### 7.3 通用周看板 + 决策

通用 6 类（获客 / 成交 / 交付 / 经济 / 客户 / 个人）每类填本周期实际值。
用户填多少就是多少，不要替他估。

然后跑：

```bash
python3 scripts/gate.py board --config opc_input.json --out OPC第二层看板.html
```

决策表 9.2 的判定由引擎给出，会带上命中的依据。念给用户听时不要替他决定，只说命中哪条、对应建议是什么。

### 7.4 记录格式

11 项里，「我的 OPC 模式」「主要收入来源」「第一层五道闸门当前状态」和五个槽位由引擎自动回填。
剩下的（本周期目标 / 继续调整暂停条件 / 数据来源和复盘日期）必须用户自己写。

### 7.5 第二层的自检

1. 有没有在候选方向产生之前就用了模式地图？（有 = 违规，引擎会拒绝）
2. 归类时用的是收入来源，还是只看了方向名？（只看方向名 = 置信度 low，必须确认）
3. 五个指标是不是用户自己从候选池里挑的？有没有我替他填？
4. 看板顶部的第一层状态还在吗？第一层没过就不能隐藏这条。
